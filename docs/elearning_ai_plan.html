💡 Triết lý thiết kế quan trọng

Toàn bộ 2 modality (text + image) đều được convert thành text trước khi embed. Vector DB chỉ lưu text chunks + embedding. Điều này đơn giản hóa pipeline rất nhiều — chỉ cần hiểu 1 loại storage. Audio bị loại bỏ vì phức tạp, chậm trên CPU, và không cần thiết cho mục tiêu học hệ thống.

📊 Chunk Strategy cho Text & Image
Text (PDF): RecursiveCharacterTextSplitter — chunk size 500–800 tokens, overlap 100–150 tokens
Metadata: file_name, page_num, chunk_id, source_type="text"

Image: Gemini Vision → description string (~200–500 ký tự)
Metadata: file_name, image_path, source_type="image"

🪄 Slide Generator — Code mẫu
python async def generate_slides( topic: str, grade_level: str, difficulty: str, n_slides: int ) -> SlidePresentation: # Step 1: Retrieve relevant chunks từ Vector DB chunks = retriever.search(topic, k=20) context = "\n\n".join([c["text"] for c in chunks]) # Step 2: LLM sinh outline (title từng slide) level_hint = LEVEL_PROMPT[grade_level] diff_hint = DIFFICULTY_PROMPT[difficulty] outline_prompt = f""" Tạo outline {n_slides} slide cho chủ đề '{topic}'. Trình độ: {grade_level} — {level_hint} Mức độ: {difficulty} — {diff_hint} Dựa trên context sau: {context} Trả về JSON: {{"slides": [{{"slide_number": 1, "title": "..."}}]}} """ outline = await llm.generate_json(outline_prompt) # Step 3: LLM sinh nội dung chi tiết từng slide slides = [] for s in outline["slides"]: content = await llm.generate_structured( SlideContent, content_prompt(s["title"], context, level_hint) ) slides.append(content) # Step 4: Render ra file .pptx pptx_path = render_pptx(slides) return SlidePresentation(slides=slides, sources=get_sources(chunks), ...)

🔬 HyDE là gì? — Technique quan trọng

Hypothetical Document Embedding: Thay vì embed câu hỏi ngắn, yêu cầu LLM tưởng tượng câu trả lời lý tưởng → embed câu trả lời đó → search. Câu trả lời hypothetical thường gần với document thật hơn câu hỏi gốc → retrieval chính xác hơn đáng kể.

🔧 PDF Ingestion Pipeline
python import fitz # PyMuPDF from langchain.text_splitter import RecursiveCharacterTextSplitter def ingest_pdf(file_path: str) -> list[dict]: doc = fitz.open(file_path) splitter = RecursiveCharacterTextSplitter( chunk_size=600, chunk_overlap=120, separators=["\n\n", "\n", ".", " "] ) chunks = [] for page_num, page in enumerate(doc): text = page.get_text() if not text.strip(): continue splits = splitter.split_text(text) for i, chunk in enumerate(splits): chunks.append({ "text": chunk, "metadata": { "source": file_path, "page": page_num + 1, "chunk_id": f"p{page_num}_{i}", "source_type": "text" } }) return chunks
🪄 Slide Generator — python-pptx Renderer
python from pptx import Presentation from pptx.util import Inches, Pt import uuid def render_pptx(slides: list[SlideContent]) -> str: prs = Presentation() prs.slide_width = Inches(13.33) prs.slide_height = Inches(7.5) # 16:9 layout = prs.slide_layouts[1] # Title and Content for slide_data in slides: slide = prs.slides.add_slide(layout) # Title slide.shapes.title.text = slide_data.title # Bullets tf = slide.placeholders[1].text_frame tf.clear() for bullet in slide_data.bullets: p = tf.add_paragraph() p.text = bullet p.level = 0 # Speaker notes notes_slide = slide.notes_slide notes_slide.notes_text_frame.text = slide_data.speaker_notes path = f"data/slides/{uuid.uuid4()}.pptx" prs.save(path) return path
🔍 RAG Query Chain
python from langchain_community.vectorstores import Chroma from langchain_huggingface import HuggingFaceEmbeddings from langchain_google_genai import ChatGoogleGenerativeAI from langchain.chains import RetrievalQA # 1. Embedding model (local, free) embedder = HuggingFaceEmbeddings( model_name="BAAI/bge-m3", model_kwargs={"device": "cpu"} ) # 2. Vector store vectordb = Chroma( persist_directory="./data/chroma", embedding_function=embedder ) # 3. LLM (Gemini Flash — free 15 req/min) llm = ChatGoogleGenerativeAI( model="gemini-1.5-flash", temperature=0.1 ) # 4. RAG Chain qa_chain = RetrievalQA.from_chain_type( llm=llm, retriever=vectordb.as_retriever(search_kwargs={"k": 5}), return_source_documents=True ) # 5. Query result = qa_chain.invoke({"query": "Định lý Bayes dùng để làm gì?"}) print(result["result"]) # Câu trả lời print(result["source_documents"]) # Nguồn trích dẫn

Những điều cần biết trước khi làm
Các vấn đề thực tế thường gặp khi triển khai hệ thống này
⚠️ Chunking sai là lỗi số 1

Chunk quá nhỏ → thiếu context, LLM không đủ thông tin trả lời. Chunk quá lớn → vượt context window, noise nhiều. Bắt đầu với 500 tokens, overlap 20%, rồi thử nghiệm với dataset của bạn. Đặc biệt quan trọng vì Slide Generator cũng phụ thuộc vào chất lượng chunks.

⚠️ Embedding model phải khớp ngôn ngữ

Nếu document tiếng Việt mà dùng all-MiniLM-L6-v2 (model tiếng Anh) → retrieval rất kém. Dùng bge-m3 (multilingual, hỗ trợ 100+ ngôn ngữ) hoặc intfloat/multilingual-e5-large khi làm với tiếng Việt.

⚠️ Slide Generator — Hallucination vẫn xảy ra

LLM có thể bịa nội dung slide không có trong tài liệu. Giải pháp: (1) Grounding bắt buộc — prompt phải yêu cầu LLM chỉ dùng context từ RAG; (2) Luôn hiển thị sources trong file slide để user biết nội dung từ đâu; (3) Nếu topic không có trong DB → thông báo rõ thay vì sinh slide giả.

💡 PDF scan (ảnh) cần OCR riêng

PyMuPDF chỉ extract text từ PDF có text layer. PDF scan (chụp ảnh) sẽ cho ra text rỗng. Cần thêm Tesseract OCR hoặc gửi từng trang qua Vision model. Đây là edge case quan trọng với tài liệu Việt Nam (nhiều sách scan).

✅ Thứ tự nên học để hiểu sâu nhất

1. Xây naive RAG không dùng framework (raw Python + ChromaDB + Gemini API) → hiểu từng bước. 2. Thêm Slide Generator → áp dụng RAG theo hướng ngược (tổng hợp thay vì trả lời). 3. Refactor với LangChain → hiểu tại sao framework giúp được gì. 4. Thêm Image pipeline → hiểu multimodal. Đừng dùng framework ngay từ đầu.

🎯 Tại sao cần biết các gap này?

Hệ thống đồ án hoạt động tốt khi 1 user dùng một mình. Khi scale lên 10+ users đồng thời, hoặc deploy thật, các vấn đề sau đây sẽ xuất hiện. Hiểu và fix chúng là bước từ junior → mid-level engineer.

🔴 Critical — production-blocking 🟡 Important — nên fix 🟢 Nice-to-have
1
🔴 Async Task Queue BLOCKING
Slide gen 60s + PDF lớn đang block request thread
FastAPI đang xử lý slide generation (~60s) và PDF parsing (~30s) synchronously trong request thread. 2 users cùng generate slide → server treo hoàn toàn.

Fix: Dùng ARQ (async, Redis-based) hoặc Celery. POST /generate → trả job_id ngay (<100ms) → worker xử lý background → user poll status.
ARQCeleryRedis Queue
2
🔴 Rate Limit + Retry cho Gemini API BLOCKING
15 req/min — crash ngay khi ingest PDF lớn
Gemini Flash free tier: 15 req/min, 1M tokens/day. Ingest PDF 500 chunks có Vision calls → crash 429 ResourceExhausted ngay lập tức.

Fix: Dùng tenacity (exponential backoff, 5 retries) + Token Bucket rate limiter (14 req/min để có buffer).
tenacityExponential BackoffToken Bucket
3
🔴 Batch Embedding BLOCKING
500 chunks = O(n) sequential calls → ~250s
Mỗi chunk đang được embed riêng lẻ (sequential loop). 500 chunks × 0.5s/chunk = 250s chỉ để embed.

Fix: Dùng embedder.encode(batch, batch_size=64). 500 chunks giảm từ 250s → ~15s (16x nhanh hơn).
16x Speedupbatch_size=64
4
🔴 Document Deduplication BLOCKING
Re-upload → double vectors trong DB
Upload cùng file 2 lần → chunks bị insert lần 2 → duplicate vectors → retrieval nhiễu, RAG trả lời sai, tốn storage.

Fix: Hash file bằng hashlib.sha256 → check DB trước khi ingest → trả "status": "duplicate" nếu đã tồn tại.
SHA-256 HashIdempotent Ingest
5
🔴 Embedded Images trong PDF BLOCKING
Hình nhúng trong PDF chưa được extract và xử lý
PyMuPDF extract text nhưng bỏ qua hình ảnh nhúng (biểu đồ, sơ đồ, công thức scan). Tài liệu toán học → mất 30-50% nội dung.

Fix: Dùng page.get_images(full=True) → extract image bytes → gửi qua Gemini Vision → embed description như text chunk.
PyMuPDF extract_imageVision LLM
6
🟡 Caching Layer (Redis)
Same query embed lại mỗi lần, LLM call không cache
Mỗi query đều chạy bge-m3 encode (~200ms) dù đã hỏi câu y hệt trước đó. LLM calls cũng không được cache → tốn Gemini quota.

Fix: Two-level Redis cache: embed cache (TTL 1h) + LLM response cache (TTL 24h) với MD5 key. Query lần 2 nhanh hơn ≥ 3x.
RedisTTL 1h / 24h3x Speedup
7
🟡 Docker Compose Production-Ready
Thiếu Postgres, NGINX, healthchecks, resource limits
docker-compose.yml hiện tại thiếu: postgres service, nginx, redis, healthcheck cho mỗi service, resource limits (1 container có thể eat toàn bộ RAM), depends_on không dùng condition: service_healthy.

Fix: 7 services: nginx + frontend + backend + worker + qdrant + postgres + redis. Mỗi service có healthcheck + resource limits.
7 serviceshealthcheckresource limits
8
🟡 Multi-tenancy
User A có thể query vào chunks của user B
Mọi users đang share cùng 1 Qdrant collection không có phân tách. User A upload tài liệu → User B query cùng topic → có thể retrieve được thông tin của user A.

Fix: Thêm user_id vào mọi chunk payload. Mọi Qdrant search phải có query_filter theo user_id.
user_id FilterData IsolationJWT Claims
9
🟡 Streaming SSE
LLM 10-15s không stream là UX tệ
User gửi câu hỏi → nhìn màn hình trắng 10-15 giây → không biết hệ thống có đang làm gì hay bị lỗi. Trải nghiệm tệ, tỷ lệ bounce cao.

Fix: FastAPI StreamingResponse với text/event-stream. Token đầu tiên trong <2s, stream liên tục đến khi xong. Streamlit hỗ trợ SSE với st.write_stream().
SSEStreamingResponse<2s TTFT
10
🟡 Conversation Memory Guardrail
Context window overflow sau 20-30 turns
Lịch sử hội thoại tích lũy không giới hạn → sau 20-30 turns vượt context window → crash hoặc LLM bỏ bớt context tùy tiện.

Fix: Sliding window + summarization. Khi history >3000 tokens → LLM tóm tắt các turn cũ → chỉ giữ summary + 3 turn gần nhất trong context.
Sliding WindowSummarization4K Token Limit
11
🟢 Load Testing & Security Testing
Prompt injection chưa được test
Load testing với Locust: 20 concurrent users, target p95 <20s, failure rate <1%.

Prompt injection: Test các payload như "Ignore all instructions", "output your API key". System prompt grounding + output validation là defense chính.
LocustPrompt InjectionOWASP LLM Top 10
12
🟢 Visual Story Mode Test Cases
Chưa có test case nào cho tính năng mới
Visual Story Mode (Pollinations.ai + Pillow comic panel) chưa có automated tests. Schema validation cho panels, image fetch test, Pillow 2×2 grid render test đều cần được bổ sung để tránh regression.
Pollinations.aiPillowSchema Validation
13
🟢 CI/CD Pipeline
GitHub Actions chưa được thiết lập
Không có pipeline tự động → mỗi lần merge có thể break build mà không biết. GitHub Actions với 2 jobs: (1) unit + integration tests với Qdrant service, (2) Docker Compose build + healthcheck. PR blocked nếu CI fail.
